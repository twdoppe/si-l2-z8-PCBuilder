## 1. Problem *(rubric A)*


Nowadays, choosing individual parts for a computer is quite a hassle. First of all, choosing a computer today does not mean that one setup will fit absolutely everyone: someone wants a simple, basic PC for uncomplicated tasks, someone else needs a reasonably capable machine for everyday duties such as work, and someone else wants maximum-performance hardware that will run all games without exception today and handle very large IT projects. Secondly, checking all components for compatibility is a complete pain, because a person has to spend a lot of time searching for everything, verifying whether the parts fit together, and finally writing it all down somewhere, remembering it, and checking if the whole build fits within the assumed budget. Therefore, our solution to this problem is a system that automatically selects all computer components according to the user's preferences, namely: the price, the specific GPU/CPU brand they want to see in their PC, and the intended purpose for which the hardware is needed. Thanks to this, at the very end we save the user's time and reduce the entire problem practically to zero (since our system generates a kind of specification at the output, which the user can later use as a reference note when building the PC).

## 2. Why AI and Why This Technique *(B · 7 pts)*


Here the question arises — why did we use rule-based reasoning in our project instead of regular code or another AI method? A standard algorithm with `if-else` conditional statements is not enough, because with so many parameters the code would become unreadable, difficult to maintain, and unable to draw new conclusions on its own. Using an alternative method (a neural network or classical machine learning) would also be inappropriate, because then the system could generate builds randomly or with errors, instead of strictly adhering to price, compatibility, and purpose rules. That is precisely why we chose rule-based reasoning, which is best suited for building our engine and guarantees full component compatibility.

## 3. Data *(B · 8 pts)*


Speaking about the data we use in our project, these are standard datasets (tables) in SQL format. In total, 7 tables are required for the project to function: `procesory`, `karty_graficzne`, `pamiec_ram`, `dyski`, `plyty_glowne`, `power_supplies`, and `pc_cases`. We downloaded some of these datasets from various repositories (e.g., GitHub), while the remaining part consists of synthetic data (generated by AI). When using these tables, we relied primarily on the technical parameters contained within them so that our system could operate properly.

## 4. Solution *(A · 10 pts, B · 5 pts)*


- System workflow:
  1. At the beginning, the user enters a budget (the amount in PLN within which the entire computer build must fit).
  2. Next, the user selects the purpose — what the computer is intended for (if they choose the gaming option, an additional option unlocks to select a preferred GPU manufacturer — NVIDIA or Radeon).
  3. In the next step, the user selects a preferred CPU manufacturer — Intel or AMD (and optionally GPU, if they previously selected gaming mode).
  4. Finally, the user clicks the "Build computer" ("Zbuduj komputer") button. The inference engine runs rules against the MySQL database and as a result, taking into account all entered parameters, the user receives a complete PC build with components selected for full technical compatibility, the chosen purpose, and the given budget.
- Description of the AI algorithm with its logical-mathematical foundation:
  1. The system uses forward chaining rule-based reasoning grounded in propositional calculus and first-order logic (`IF condition_1 AND condition_2, THEN conclusion`), which allows deriving new facts from user input data (e.g., calculating the required power supply wattage reserve based on the sum of TDP power draw of the selected processor and graphics card).
  2. State-space search is performed using branch pruning (rejecting entire groups of incompatible parts at an early stage of inference, e.g., by matching the CPU `socket` and `memory_type`), instead of checking every combination one by one.
  3. Selecting the best build from matching variants is handled by a fitness evaluation function that maximizes budget utilization without exceeding it and minimizes the performance gap between CPU and GPU (avoiding bottlenecks), following the rule: `Score = (Sum of component prices / Budget) - performance disparity penalty`, subject to the condition that the sum of prices does not exceed the budget.

- Key parameters and their values:
  1. Budget allocation by purpose preset (percentage weights):
     - Gaming: 45% of the budget is allocated to the graphics card (GPU), and 22% to the processor (CPU).
     - Workstation: 30% to the GPU and 35% to the CPU.
     - Office: 0% to a dedicated GPU and 40% to a CPU with an integrated GPU.
  2. Dynamic budget rollover and cooling reserve:
     - The amount saved on one component is automatically added to the limit of subsequent components (e.g., for a larger-capacity SSD or more RAM).
     - If the selected processor has a $\text{TDP} > 65\text{ W}$, the engine automatically reserves between 100 and 300 PLN for a CPU cooling system.
  3. Anti-Bottleneck rule and Future-proof mode:
     - When selecting a high-end graphics card (high / enthusiast segment), the system enforces a processor equipped with at least 6 cores.
     - Checking the Future-proof option restricts selection exclusively to platforms based on DDR5 memory.
  4. Power supply (PSU) wattage reserve and hard compatibility rules:
     - Power supply wattage is calculated within a safe corridor of $1.25\times\text{–}1.65\times$ the build's actual power demand.
     - Full hardware compatibility is enforced: processor socket (`CPU.socket == MOBO.socket`), memory standard (`DDR4` / `DDR5`), motherboard form factor with the case (`ATX`, `Micro-ATX`), and support for the required GPU power connector (e.g., `12V-2x6` / `PCIE5`).

Evaluation conclusions (honest assessment of strengths and weaknesses):
In 6 out of 8 cases, our expert system clearly outperforms pre-built store PCs in gaming performance, GPU tier, and VRAM capacity (especially in the Gaming segment, where stores in the 7,000–10,000 PLN range install i5 / Ultra 5 processors and RTX 5060-class cards, whereas our system selects specialized Ryzen 7 7800X3D / 9850X3D units and cards ranging from RX 7800 XT up to RTX 5070 Ti). However, the limitations of our database should be honestly noted: in lower gaming budgets (7,000–8,000 PLN) and office configurations, the engine reaches for previous-generation chips (e.g., RX 7800 XT, RTX 4070 Ti, or Intel 14th Gen), which offer higher raw performance for their price but feature higher power consumption (TDP) than the newest chips offered by retail stores. In 2 office cases (07 and 08), retail builds achieve a comparable level, winning in acoustics and energy efficiency. Algorithmically, the engine maintains a complete advantage over a simple cascade filter — instead of searching the full Cartesian product of tables, it reaches a decision in 10–11 rules in under 0.05 s.

## 6. Non-functional Requirements *(A · 5 pts)*


The time needed to select a computer build according to the user's requirements usually takes less than 1 second (sometimes taking up to 1.4–1.5 seconds). We resolved the issue of what happens when a user enters invalid data as follows: when incorrect values are provided (for example, a price below the minimum), the system displays a budget error message (informing that it must be higher than the minimum specified amount). Results for individual components (particularly regarding the CPU) may occasionally repeat.

## 7. Limitations *(E · 4 pts)*


We have a specific case where our system may fail: when selecting, for example, a budget between 1,500 and 4,500–5,000 PLN, the system is unable to find suitable components that would fit within this amount. If we had significantly more time, we would refine the price category logic itself (perhaps the system would select a partial PC build without certain components or operate differently) — either way, we would resolve this issue given more time to develop the project.

## 8. Practical Applications *(E · 4 pts)*


Similar expert systems and configurators based on compatibility rules are widely used in e-commerce and computer/electronics retail:
 1. Computer stores and PC configurators: The best-known examples are the PCPartPicker platform, and on the Polish market, build configurators in stores such as x-kom, Morele.net, or Komputronik. They use component parameter knowledge bases to automatically block the selection of incompatible parts (e.g., a motherboard with a different socket than the chosen processor) and calculate power supply wattage requirements.
 2. B2B sales support and IT consulting: Rule-based systems are used by procurement departments and hardware distributors (e.g., Dell, Lenovo) to quickly create customized workstations and servers tailored to specific business and budget requirements of a client, without needing to involve a sales engineer every time.
 3. Product configurators in other industries (CPQ – Configure, Price, Quote): Analogous rule-based reasoning logic is used, among others, in the automotive industry (car configurators where choosing a specific engine enforces a particular type of gearbox and suspension) and in industry when selecting automation components.

## 10. How to Run *(C · 4 pts)*

To run the project locally on your own computer, follow the steps below:

1. Prerequisites:

- Installed Python 3.11+

- Installed XAMPP package (with the MySQL database server running on the default port 3306, user `root`, no password)

2. Database preparation:

- Launch XAMPP Control Panel and start the MySQL module (as well as Apache if you want to use phpMyAdmin).

- Open the `http://localhost/phpmyadmin` panel, create a new database named `pckonfig`, and import the prepared SQL tables into it (`procesory`, `karty_graficzne`, `plyty_glowne`, `pamiec_ram`, `dyski`, `pc_cases`, `power_supplies`).
3. Cloning the repository and installing dependencies:
- Open a terminal and enter sequentially:

```
git clone https://github.com/twdoppe/si-l2-z8-PCBuilder
cd si-l2-z8-PCBuilder/pcbuilder
pip install flask pymysql

```
4. Running the application:
- In the project directory, start the Flask server with the command:

```
python app.py

```
5. Output:
- After starting the server, open a web browser and go to:

```
http://127.0.0.1:5000/

```
A form will appear on the screen where you enter your budget, select the computer's purpose and hardware preferences, and after clicking the "Zbuduj komputer" ("Build computer") button, the system will display a ready, compatible set of components along with reasoning logs and the option to download the configuration to a `.txt` file.
